# agent-hours v1.1.0 — Claude Code and Codex

agent-hours now tracks active agent time across both Claude Code and Codex, locally,
with one combined report. It remains one Node.js file with zero dependencies, no
account, no telemetry and no runtime network calls.

## What you get

- **Agent active**: merged wall-clock time while at least one Claude Code or Codex
  turn was running. Overlapping sessions count once.
- **Turn time**: every turn summed, including parallel work.
- Per-project totals using canonical git roots, with same-named repositories safely
  disambiguated.
- Per-agent Claude Code and Codex totals in terminal, HTML and JSON reports.
- Immediate history recovery from local Claude Code and Codex transcripts.

This measures agent activity. It does not measure reading, thinking or manual work
between prompts and is not an automatic billing total.

## Codex support

Live tracking uses Codex's documented `UserPromptSubmit`, `Stop` and `SessionEnd`
hooks. Historical backfill reads structural boundaries from `$CODEX_HOME/sessions`
(normally `~/.codex/sessions`) and recognizes completed and aborted turns. Codex
subagent rollouts are excluded because the parent turn already covers their
orchestration interval.

The installer understands both `$CODEX_HOME/hooks.json` and inline hooks in
`config.toml`. It prints only missing entries, warns about exact duplicates and hooks
disabled under `[features]`, and never rewrites the config itself. After installation,
Codex users review and trust the commands through `/hooks`.

Codex does not document a `StopFailure` lifecycle hook, so that event remains Claude
Code-only.

## Reliability and privacy

- Live and backfill data records timestamps, source, event, session id, optional turn
  id and working directory—never prompts, replies, tool arguments or file contents.
- Backfill reads transcript structure but does not copy, retain or transmit content.
- Session and turn identities include their source, preventing coincidentally equal
  Claude Code and Codex ids from colliding.
- Daily durations are clipped at the configured work-day boundary, keeping headline
  totals and the HTML hour grid consistent for turns that cross 05:00, including
  daylight-saving transitions.
- Backfill is private and atomically replaced. An unrecognized non-empty transcript
  set fails closed and leaves the previous history untouched.
- Logs and exported HTML are owner-only on POSIX; Windows remains supported without
  relying on POSIX permission behavior.
- The local server remains bound to `127.0.0.1`.

## JSON compatibility

Existing scripts keep working: `wallMinutes`, `turnMinutes`, `turns`, days and project
fields retain their meaning. v1.1.0 adds `bySource` and optional source/turn metadata.
Old live and backfill JSONL remains readable.

Example:

```json
{
  "wallMinutes": 2143,
  "turnMinutes": 2626,
  "turns": 571,
  "bySource": {
    "claude": 1471,
    "codex": 847
  }
}
```

Per-source wall time can add up to more than combined `wallMinutes` when the two
agents overlap. The combined value still counts that overlap once.

## Install or upgrade

Paste this into Claude Code or Codex:

```text
Install agent-hours for me: https://raw.githubusercontent.com/DrebotAI/agent-hours/v1.1.0/docs/install.md
```

The install guide pins the immutable `v1.1.0` source. It preserves third-party hooks,
stops on malformed JSON and does not replace an existing Claude Code status line.
Existing v1.0.x JSONL data requires no migration.

Requires Node 20.1 or newer. Restart configured agents afterward; Codex users must
review the hook commands with `/hooks`.

## Accuracy limits

The 30-minute idle-gap rule removes sleep and abandoned tool activity but can also
omit a genuinely long, silent tool call. An abruptly killed terminal may be capped at
four hours. Claude interruptions are inferred from the last meaningful activity;
Codex uses timestamped aborted-turn structure.

Codex states that transcript format is not a stable hook interface. v1.1.0 uses a
small structural adapter and a fail-closed guard, but a future Codex update can still
require an agent-hours patch. Live hooks use the documented lifecycle interface and
are the more stable path going forward.

The transcript audits and local rollout smoke tests behind these defaults are local
observations, not universal accuracy guarantees.
